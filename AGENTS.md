# AGENTS.md

- Spring Boot 3.2.3 single-module Maven app (`com.ldz.park.ParkApplication`) on Java 21; use the Maven wrapper, but in this checkout `mvnw` may not be executable, so `bash ./mvnw ...` is safer than `./mvnw ...`.
- Useful commands: `bash ./mvnw test`, focused test `bash ./mvnw -Dtest=ParkApplicationTests test`, package `bash ./mvnw clean package`; Docker build also packages with `-DskipTests`.
- Tests compile with `pom.xml` release 21; if Maven fails with “不支持发行版本 21”, the local JDK is too old, not necessarily the code.
- Default active profile is **`dev`** in `src/main/resources/application.properties`; containers run dev profile (docker run does not override it) with real values injected via env. Activate prod explicitly with `--spring.profiles.active=prod` or `SPRING_PROFILES_ACTIVE=prod` — prod has no defaults for `mysql.url`/`jwt.secret`/COS keys and fails fast when they are missing.
- Database config is custom `mysql.*` properties wired by `config/MySQLConfiguration.java`, not standard `spring.datasource.*`; it appends `allowMultiQueries=true` when creating the Hikari datasource.
- MyBatis mapper interfaces live in `src/main/java/com/ldz/park/dao` and XML SQL lives in matching `src/main/resources/com/ldz/park/dao/*.xml`; keep interface method names and XML statement ids in sync.
- Controller/service pattern is `web/*Controller` -> `service/*Service` -> `dao/*Mapper`; API responses generally use `model/meta/ApiResponse` and pagination uses PageHelper `PageInfo` plus `ApiResponse.successWithPage`.
- JWT auth is enforced by `security/UserSecurityInterceptor` for `/**`; only `/api/login`, `/api/register`, `/api/sso/**`, Swagger/OpenAPI assets, `/lib/**`, and `/favicon.ico` are excluded. Use `Authorization: Bearer <token>`.
- Swagger UI is configured at `/swagger-ui.html` but disabled in `application-prod.properties`; enable/use a non-prod profile for API docs.
- Do not run MyBatis generator casually: `src/main/resources/generatorConfig.xml` now holds placeholders; it targets whatever DB you fill in and writes generated Java into `src/main/java`.
- No secrets in the repo (removed 2026-11-09; history still contains old leaked values, pending rotation). All credentials are env-injected: `MYSQL_URL`, `MYSQL_USER`, `MYSQL_PASSWORD`, `JWT_SECRET`, `COS_SECRET_ID/KEY`, `WECHAT_MINIAPP_APP_ID/SECRET`. Do not reintroduce hardcoded values, defaults, or placeholder secrets in properties/config classes.
- WeChat mini-program silent login: the applet calls `POST /api/wechat/auth/mini-login` (also legacy `POST /api/oauth/mini/login`, `POST /api/wx-login`); it reads `WECHAT_MINIAPP_APP_ID` / `WECHAT_MINIAPP_SECRET` from env; empty values cause `WECHAT_CONFIG_ERROR`. See `docs/mini-login.md`.
- **CI/CD (`.github/workflows/docker-publish.yml.yml`): every push to `main` = immediate production deploy.** Build → push ACR (`park_java/park-java:{sha}` + `:latest`) → SSH to the JD Cloud server, `docker rm -f park-java` and run the new image with `--env-file /data/park/java.env` (all secrets live in that root:600 file on the server, NOT in GitHub or the image; the deploy script aborts before removing the old container if the file is missing). Backend downtime per push ≈15–30s. **After any deploy, run the verification checklist in `docs/deployment.md` §5 — a green CI run does not mean the app is alive.** Rollback = re-run the container with the previous sha tag (§6).
- Dockerfile uses Eclipse Temurin 21, runs `./mvnw clean package -DskipTests`, exposes **3429** (`server.port=${port:3429}`); prod runs behind nginx on the server (kolder.site `/api/` → 127.0.0.1:3429).
- The mini program and admin UI both call the backend through `https://kolder.site`; `wx-mini.greandata1.com` is unrelated to this system at runtime. Full flow, topology, verification and rollback procedures: **`docs/deployment.md`**.
